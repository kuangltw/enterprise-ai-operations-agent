# 0006 瀏覽器沿用短效工作階段

日期：2026-11-13

## 背景

React 將登入 JWT、使用者與租戶存於頁面記憶體，重新載入後沒有憑證可以呼叫 `/auth/me`。API 已以 PostgreSQL 工作階段限制 JWT 的有效期與撤銷狀態。

## 決策

- 瀏覽器使用 `POST /auth/session` 登入，沿用密碼驗證、速率限制及 JWT 簽發，將憑證置於主機限定的 `HttpOnly`、`Secure`、`SameSite=Strict` Cookie，路徑限 `/api/v1`。使用與現有 JWT 相同的 15 分鐘絕對期限；重新載入不延長期限。API 用戶端可繼續使用 `POST /auth/login` 取得 Bearer JWT。
- 前端與 API 由同一來源提供。Cookie 模式的非安全方法及瀏覽器登入要求固定的自訂請求標頭，瀏覽器跨來源帶此標頭須先取得 CORS（跨來源資源共用）預檢許可。應維持目前同來源部署與無跨來源授權的配置。正式環境使用 HTTPS，本機驗證使用瀏覽器信任的 loopback 位址。
- 前端載入時先查詢 `/auth/me`，再查可存取租戶與目前租戶。僅將目前使用者選擇的租戶 ID 暫存於分頁的 `sessionStorage`，作為 `X-Tenant-ID` 提示。角色及角色權限來自後端即時核對；實際請求仍須通過租戶、ACL 與倉庫範圍的授權。
- 登出在資料庫提交撤銷後刪除 Cookie。後端每次驗證使用者狀態、JWT 與工作階段；即使 Cookie 尚在，已撤銷或過期的工作階段仍回 401。

## 取捨

以現有工作階段支援頁面重新載入，因此無須新增 Refresh Token、輪替或延長登入週期。工作階段逾期仍需重新輸入帳密。HttpOnly 降低權杖被 JavaScript 讀取的風險，仍須維持頁面 XSS（跨網站指令碼）防護。
